# OpenSpec — opcua-scan

Reverse-engineered, implementation-ready specification for the `opcua-scan` CLI, written in the
[OpenSpec](https://github.com/Fission-AI/OpenSpec) convention.

## Contents
- [spec.md](spec.md) — overview, goals/non-goals, capabilities & requirements (SHALL/WHEN/THEN),
  data model, interfaces, dependencies, env/config, deployment, testing, repo map.
- [architecture.md](architecture.md) — runtime architecture, module boundaries, concurrency model,
  data flow, invariants, failure handling.
- [assumptions.md](assumptions.md) — uncertainty register (Confirmed / Likely / Assumption).
- components/
  - [cli.md](components/cli.md) — command surface, flags, defaults, per-command orchestration.
  - [opcua-layer.md](components/opcua-layer.md) — async-opcua wrapper (connect/browse/attrs/value/ns/history).
  - [scanner.md](components/scanner.md) — concurrent traversal engine + stats.
  - [filters.md](components/filters.md) — path patterns + attribute predicates.
  - [export.md](components/export.md) — `NodeRecord` contract + tree/table/json/ndjson/csv.
  - [acquire.md](components/acquire.md) — config schema, selection, sinks, orchestration, config-gen.
  - [subscription.md](components/subscription.md) — monitored items: validate/sample/live.
  - [tui.md](components/tui.md) — interactive explorer + acquire-config generation.
  - [config-profiles.md](components/config-profiles.md) — YAML profiles + namespace cache.

## How to use this spec
- **Onboarding:** read `spec.md` → `architecture.md` → the component(s) you'll touch.
- **Planning a change:** find the owning component doc's "Extension points"; cross-check invariants
  in `architecture.md §6`.
- **AI-assisted PRs:** point the agent at the relevant component doc + `assumptions.md` to avoid
  re-deriving structure.

## Evidence labels
`[Confirmed]` verified in source · `[Likely]` strongly implied · `[Assumption]` needs validation.
