## Acquisition config migration

Legacy files remain supported. For a server with this complete two-entry namespace
table (`http://opcfoundation.org/UA/`, `urn:example:factory`), the following representative
configs select the same node and preserve its output name, mode, cached path, and tasks.

Before:

```toml
[connection]
endpoint = "opc.tcp://localhost:4840"
name = "Factory"

[[selection.node]]
id = "ns=1;i=1001"
namespace = "urn:example:factory"
name = "Temperature"
mode = "poll"
path = "Factory/Temperature"

[output]
format = "ndjson"

[[task]]
mode = "poll"
interval = "1s"
```

After:

```toml
[[device]]
name = "Factory"
protocol_address = { endpoint = "opc.tcp://localhost:4840", namespaces = ["http://opcfoundation.org/UA/", "urn:example:factory"] }

[[device.point]]
id = "ns1-i1001" # stable unique logical key, not an output name
address = { node_id = "ns=1;i=1001" }
name = "Temperature"
mode = "poll"
path = "Factory/Temperature"

[output]
format = "ndjson"

[[task]]
mode = "poll"
interval = "1s"
```

Move existing connection/security fields directly onto the device, except `endpoint`,
which moves into `protocol_address`. Preserve all `[acquire]`, `[output]`, `[[task]]`,
and `[selection]` discovery filters. Use exactly one device per file; multiple files go
in `--config-dir`. Keep every ordered namespace slot: no sorting, compaction, or
deduplication. With an array, missing mappings fail safely without numeric fallback;
without it, addresses keep literal indexes as before. Implicit/explicit namespace 0
is always the standard OPC UA namespace.

Acquisition and `browse --tui` / `browse --config` bypass disk namespace caches and
read the active session table. This does not add reconnect re-resolution, MQTT
publishing, full tedge-dot compatibility, or security guarantees. Modes and cached
paths remain tool-specific. See [acquire.md](components/acquire.md) for details.
